# 免安装使用指南

本文档说明如何在**不做 pip 安装**的前提下直接从源码运行 IRIS（鸢尾），适用于
Windows / WSL / Git Bash 环境。

> 本文档由 `HOW_TO_USE.md`、`README_USAGE.md`、`QUICK_START.md`、
> `INSTALLATION_INSTRUCTIONS.md`、`INSTALLATION_COMPLETE.md` 五份文档归并去重而成。
> 原文中的 CMD 与 Bash 语法混用、规则条数不一致等问题已按实测结果修正。

---

## 1 为什么推荐免安装

pip 安装方式在本项目上遇到过多重阻碍：

- **权限**：系统级 `pip install` 需要管理员权限，用户级 `--user` 安装路径分散；
- **文件锁**：Windows 上运行中的 `iris.exe` 无法被覆盖或删除，导致
  `pip install -e . --upgrade` 中断（`Zip archive with extra data` 报错）；
- **残留**：卸载后 `Scripts/` 目录仍留有 `iris.exe` 包装器，且它指向的路径已不存在，
  命令行调用会直接失败；
- **污染**：site-packages 中存在多版本残留时，`import iris` 加载到的是旧代码，
  调试时出现"改了代码但行为没变"的假象。

相比之下，源码直跑方案**零权限、零污染、可移植、可调试**：改完代码立即生效，
IDE 直接断点，卸载只需删目录。

如果确实需要系统安装（例如为了让 `iris` 短命令在任何目录下可用）：

```bash
pip install -e .
```

装完后验证：

```bash
pip show iris
iris --help
```

> 注意：`pip install` 会创建 `iris` 命令，但**项目要求从项目根目录启动**
> （见 §2.3），否则规则目录探测会失败。

## 2 环境准备

### 2.1 已验证环境

| 组件 | 版本 |
|---|---|

| Docker | 最新版 |

### 2.2 设置 PYTHONPATH

三端写法各不相同，**分隔符与变量展开语法也不同，混用会失效**。

**Windows CMD**

```bat
cd /d "D:\桌面资料\临时工作区\IRIS"
set PYTHONPATH=D:\桌面资料\临时工作区\IRIS\src;%PYTHONPATH%
python -m iris.cli rules list
```

**PowerShell**

```powershell
cd "D:\桌面资料\临时工作区\IRIS"
$env:PYTHONPATH = "D:\桌面资料\临时工作区\IRIS\src;" + $env:PYTHONPATH
python -m iris.cli rules list
```

**Bash（WSL / Git Bash）**

```bash
cd "/d/桌面资料/临时工作区/IRIS"
export PYTHONPATH="/d/桌面资料/临时工作区/IRIS/src:$PYTHONPATH"
python3 -m iris.cli rules list
```

> 变量名是 `PYTHONPATH`，**不是 `PATH`**。写进 `PATH` 不会让 `import iris` 生效。

### 2.3 必须从项目根目录启动

`src/iris/config.py` 的 `Settings.rules_dir` 会从当前工作目录**逐级向上查找同时包含
`rules/` 与 `src/` 子目录的目录**，返回其 `rules/`：

```python
for base in [Path.cwd().resolve(), *Path.cwd().resolve().parents]:
    if (base / "rules").is_dir() and (base / "src").is_dir():
        return base / "rules"
return Path("rules")
```

在项目根以外的目录启动时，上溯找不到项目根，`rules_dir` 回退为相对路径 `rules`，
`load_rules()` 会**加载到 0 条规则**——仿真能跑，但所有 L3 修复静默失效。这是排查
"规则好像没生效"时的第一检查项。

### 2.4 永久生效

**Windows 图形界面**：`Win+R` → `sysdm.cpl` → 高级 → 环境变量 → 用户变量中新建
`PYTHONPATH`，值为 `D:\桌面资料\临时工作区\IRIS\src`。

**PowerShell Profile**（写入
`$HOME\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`）：

```powershell
$env:PYTHONPATH = "D:\桌面资料\临时工作区\IRIS\src;" + $env:PYTHONPATH
```

**Bash（`~/.bashrc`）**：

```bash
echo 'export PYTHONPATH="/d/桌面资料/临时工作区/IRIS/src:$PYTHONPATH"' >> ~/.bashrc
source ~/.bashrc
```

### 2.5 批处理启动器

在项目根创建 `start_iris.bat`：

```batch
@echo off
cd /d "%~dp0"
set PYTHONPATH=%CD%\src;%PYTHONPATH%
python -m iris.cli %*
```

之后可直接用：

```bat
start_iris.bat rules list
start_iris.bat emulate list
```

`%~dp0` 取批处理自身所在目录，因此该文件放到任何位置都能正确定位项目根。

## 3 四种启动方式

### 3.1 方式一：PYTHONPATH + CLI（推荐）

见 §2.2。这是日常使用方式，命令为 `python -m iris.cli <子命令>`。

若已 pip 安装，可直接用短命令 `iris <子命令>`。

### 3.2 方式二：脚本内注入 sys.path

适合在自定义脚本、notebook 中调用 IRIS 的内部 API：

```python
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).parent / "src"))

from iris.rules.engine import load_rules
from iris.config import get_settings

rules = load_rules(get_settings().rules_dir)
print(f"[OK] Loaded {len(rules)} rules")
for rule in rules:
    print(f"  {rule.id:<32} stage={rule.stage}")

from iris.monitor.ai_guardian import AIHealthMonitor, SerialLogAnalyzer
print("[OK] AI Guardian modules ready")

from iris.emulate.auto import prepare_from_firmware, prepare_from_rootfs
print("[OK] Emulation prep functions ready")
```

用相对路径 `Path(__file__).parent / "src"` 时，脚本必须放在项目根目录。

### 3.3 方式三：REPL 中直接调用 `app([...])`

```python
>>> import sys
>>> sys.path.insert(0, 'D:/桌面资料/临时工作区/IRIS/src')
>>> from iris.cli import app
>>> app(['rules', 'list'])
>>> app(['emulate', 'list'])
```

`app` 是 Typer 应用对象，接受 click 风格的参数列表，等价于命令行调用。

### 3.4 方式四：CLI 封装器

在项目根创建 `iris_run.py`：

```python
#!/usr/bin/env python
"""IRIS 命令行封装：把任意 iris 子命令暴露为普通 python 脚本调用。

用法：
    python iris_run.py rules list
    python iris_run.py emulate list
    python iris_run.py emulate guardian-start 10001 --interval 30
"""
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).parent / "src"))


def main() -> int:
    if len(sys.argv) < 2:
        print(__doc__)
        return 1

    from iris.cli import app

    try:
        app(sys.argv[1:], standalone_mode=False)
    except SystemExit as exc:
        return int(exc.code or 0)
    except Exception as exc:  # noqa: BLE001 - 封装器需把异常转成退出码
        print(f"Error: {exc}")
        return 1
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

## 4 常用命令速查

| 命令 | 说明 |
|---|---|
| `db init` | 初始化数据库全部表 |
| `db check` | 检查数据库连通性 |
| `extract inspect <firmware>` | 分析固件格式、架构、uImage 头、squashfs 偏移、分区表 |
| `extract add <firmware> --brand <brand>` | 固件入库 |
| `extract rootfs <firmware>` | 提取 rootfs 并校验架构 |
| `corpus list` / `corpus download` | 查看 / 下载语料清单中的固件 |
| `rules list` | 列出全部 L3 规则 |
| `rules apply <rootfs> [--apply]` | 对 rootfs 应用规则（默认 dry-run） |
| `emulate run <firmware>` | 一键固件 → 仿真运行（核心命令） |
| `emulate list` | 列出所有仿真容器 |
| `emulate status <iid>` | 容器详情 + 端口映射 + HTTP 探活 |
| `emulate stop <iid>` | 停止并删除容器 |
| `emulate guardian-start <iid> [--interval 30]` | 启动 AI 值守持续监控 |
| `serve start [--host --port]` | 启动 FastAPI 服务（默认 0.0.0.0:9000） |

`emulate run` 常用参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--arch` | `auto` | 目标架构；`auto` 由 ELF 普查推断 |
| `--iid` | 自动 | 容器 ID |
| `--port` | `0`（自动分配） | 宿主映射端口，自动分配范围 8080–8199 |
| `--timeout` | `120` | 等待 Web 可达的秒数 |
| `--force` | 关 | 跳过架构预检 |
| `--apply-rules / --no-apply-rules` | 应用 | 是否应用 L3 规则 |
| `--parts-dir` | 无 | TendaW 多分区 rootfs 组装目录 |

典型组合（双终端工作流）：

```bash
# 终端 1：启动仿真（L3 规则自动应用）
python -m iris.cli emulate run D:/path/to/firmware.bin --iid 10008 --port 8999 --timeout 300

# 终端 2：开启值守监控
python -m iris.cli emulate guardian-start 10008 --interval 30
```

## 5 快速自检

### 5.1 基础能力

```bash
cd /d "D:\桌面资料\临时工作区\IRIS"
```

规则清单（`rules/` 目录实测，共 7 条）：

| 规则 ID | 阶段 | 作用 |
|---|---|---|
| `dev-extended-nodes` | boot | 静态 busybox mknod 扩展 16 组 mtd 设备节点 |
| `generic-diag-crash-fix` | service | 禁用 SIGSEGV 死循环的 `diag` 诊断工具 |
| `generic-watchdog-guard` | service | 通用 watchdog 防护（7 类命名变体与符号链接） |
| `mtd-name-lookup-guard` | nvram | 指纹标记：检测 `/proc/mtd` 按名查询模式 |
| `shadow-jffs2-opt` | service | 注释会遮蔽已有内容的 JFFS2 重挂载行 |
| `tenda-web-server-forced-start` | service | 强制拉起 goahead / boa |
| `vendor-watchdog-monitor` | service | 禁用厂商 watchdog 守护进程 |

## 6 故障排查

| 症状 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: No module named 'iris'` | PYTHONPATH 未设置 | 设置 §2.2，或脚本内 `sys.path.insert` |
| `rules list` 输出 0 条 | 未从项目根启动 | `cd` 到项目根（§2.3） |
| `iris` 命令找不到 | 未 pip 安装，或 Scripts 下有失效残留 | 改用 `python -m iris.cli`；检查并删除残留的 `iris.exe` |
| `pip install -e .` 报文件被占用 | `iris.exe` 正被进程使用 | `taskkill /F /IM iris.exe`，停掉运行中的仿真容器后重试 |
| 找不到固件文件 | 路径错误 | 用绝对路径；语料在 `iris-home/corpus/` |
| `Permission denied` | Docker 未以管理员启动 | 以管理员身份运行终端后 `net start docker` |
| 容器无法启动 | 残留同名容器 | `docker stop iris-qemu-*` 与 `docker rm iris-qemu-*` 后换新 iid 重试 |
| 规则执行了但无效果 | 规则动作在 chroot 内执行，日志在 guest 内 | 查容器内 `/etc/scripts/boot_fixes.log` |

## 7 IDE 集成

在 VSCode / PyCharm 中：

1. 将项目根目录设为工作目录（保证规则目录探测成功）；
2. 在 Python 解释器配置中把 `src` 加入 `PYTHONPATH`，或直接在 `.vscode/settings.json`
   中设置 `python.analysis.extraPaths`；
3. 集成终端复用 `start_iris.bat` 的写法（`cd /d %~dp0` + 设置 PYTHONPATH）。

这样即可在 IDE 内对 `src/iris/**` 直接断点调试，修改立即生效。
